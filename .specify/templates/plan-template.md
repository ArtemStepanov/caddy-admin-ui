## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- **Preserve Caddy Configuration**: Does the design avoid losing unsupported or
  unknown Caddy route data during import, edit, export, and sync?
- **Secure the Admin Surface**: Are bind address, authentication, input validation,
  and secret handling covered for any exposed admin UI/API?
- **Test Sync-Critical Paths**: Are tests planned for API mutations, config
  building/parsing, import/export, storage, authentication, or Caddy schema changes
  touched by this feature?
- **Keep the Stack Small**: Are new dependencies, services, databases, or framework
  changes avoided unless justified by a current requirement?
- **Observable and Recoverable Operations**: Will users see Caddy connectivity, sync
  warnings, and actionable non-secret errors when operations partially fail?
