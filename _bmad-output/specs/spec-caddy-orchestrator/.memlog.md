- (direction by Artem) target project is caddy-orchestrator; identify inconsistencies across planning artifacts
- (decision) adopt Architecture Spine and UX consensus resolving earlier PRD divergences: canonical Caddyfile CST, staged draft pipeline, decoupled read-only Docker discovery, 4 TLS scenarios, and multi-horizon verification
- (decision) master configuration format is Caddyfile text with lossless CST preserving comments, whitespace, and # @id: <uuid> entity annotations
- (decision) configuration changes stage in a singleton SQLite DraftState; publication requires explicit Apply with optimistic ETag concurrency check and atomic POST /load
- (decision) Caddy Admin API POST /adapt is used for remote compilation and plugin validation; manager container does not bundle local Caddy binary
- (decision) verification pipeline is asynchronous and typed, evaluating HTTP, redirect, file-server, and TLS certificate reachability across manager_network and client_perspective vantages
- (decision) DNS provider credentials for DNS-01 challenges are encrypted at rest with AES-GCM-256 and redacted from logs, diffs, and exports
- (decision) Docker container discovery is optional, read-only (GET /containers/json), and never requests write permissions or manages container lifecycles
- (capability) CAP-1: Explicit Adoption & Connection to Existing Caddy
- (capability) CAP-2: Dual-Mode Route and Configuration Authoring
- (capability) CAP-3: Destination and Upstream Specification with Optional Container Discovery
- (capability) CAP-4: Staged Multi-Change Batching and Unified Diff Review
- (capability) CAP-5: Atomic Configuration Publication with Concurrency Fencing
- (capability) CAP-6: Multi-Horizon Asynchronous Service Verification
- (capability) CAP-7: Comprehensive TLS Certificate Management Across Four Scenarios
- (capability) CAP-8: Failure Diagnosis and Ambiguous State Recovery
- (capability) CAP-9: Snapshot Rollback and Disaster Recovery
- (capability) CAP-10: Accessible, Responsive Operator Interface
- (constraint) manager-only Docker Compose container connecting over network to external Caddy; local bundled Caddy is strictly a test fixture
- (constraint) external Caddy deployment must run with --resume and mount persistent /config and /data volumes to prevent configuration loss on reboot
- (constraint) Caddy Admin API must be network-isolated to loopback or private bridge network without public exposure
- (constraint) recovery snapshots retain a maximum FIFO buffer of 100 entries in SQLite
- (non-goal) fleet management or multi-instance Caddy clustering
- (non-goal) multi-user access control, RBAC, or enterprise SSO
- (non-goal) container lifecycle management or automated Docker publication triggers
- (non-goal) continuous metrics, analytics platform, or historical traffic telemetry
- (non-goal) automated database migration from Nginx Proxy Manager or other reverse proxies
